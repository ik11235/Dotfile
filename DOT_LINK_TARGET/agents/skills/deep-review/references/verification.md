# 敵対的検証（指摘の反証）

レビュアーが出した指摘を、別のサブエージェントに**否定させる**。
否定しきれなかった指摘だけが報告に残る。誤検知を鵜呑みにして直すと、動いていたコードを壊すほうが高くつくため。

## 渡すもの・渡さないもの

- 渡す: 指摘 1 件（または同一ファイルの指摘数件）、作業ディレクトリのパス、diff の取得コマンド、ガイドラインファイルのパス一覧
- 渡さない: レビュアーの他の指摘、どの観点から出たか、変更の意図の説明（検証者が意図に引きずられて擁護/同調するのを防ぐ）

## 指示テンプレート

```
以下のコードレビュー指摘は誤検知かもしれません。あなたの仕事はこの指摘を**否定する**ことです。
実際のコードを読み、指摘された失敗シナリオが本当に成立するかを確かめてください。

否定の材料になるもの:
- 呼び出し元・既存のバリデーション・型・フレームワークやライブラリの保証によって、そのシナリオに到達しない
- 失敗シナリオの前提（入力・状態）が現実には発生しない
- 指摘が引用しているガイドライン/コメント/過去 PR が、実際にはそう言っていない、または別の箇所の話である
- 問題は変更前から存在しており、この diff が生んだものではない
- lint・型チェック・CI が確実に検出する種類の問題である

可能なら、テストや小さなスクリプトで再現を試みてください（リポジトリのファイルは変更しないこと。一時ファイルは作業ディレクトリの外に置く）。
判断が付かない場合は REFUTED ではなく PLAUSIBLE にしてください。

## 指摘
<severity / file:line / 問題点 / 失敗シナリオ / レビュアーが示した根拠>

## 対象
- 作業ディレクトリ: <path>
- diff の取得: <コマンド>
- ガイドラインファイル: <パス一覧>

## 出力
- verdict: CONFIRMED | PLAUSIBLE | REFUTED
- confidence: 0 / 25 / 50 / 75 / 100（下のルーブリック）
- 根拠: 実際に読んだコード（file:line）や実行結果に基づく説明。CONFIRMED なら再現手順
- severity の見直し: レビュアーの重大度が過大/過小なら修正後の値と理由
```

## 判定

- **CONFIRMED** — 失敗シナリオの成立をコードまたは実行で確認できた
- **PLAUSIBLE** — 否定する材料が見つからないが、成立も確認しきれない
- **REFUTED** — 上の「否定の材料」のいずれかで成立しないと示せた

## 確信度ルーブリック（公式 plugin の基準を踏襲。検証者にそのまま渡す）

- **0**: まったく確信がない。軽い精査にも耐えない誤検知、または既存の問題
- **25**: やや確信がある。本物かもしれないが確認できなかった。スタイルの指摘で、ガイドラインに明記されていないもの
- **50**: そこそこ確信がある。本物だと確認できたが、細かい指摘か、実際にはめったに起きない
- **75**: 強い確信がある。再確認し、実際に踏む可能性が非常に高いと分かった。機能に直接影響する、またはガイドラインが明示している問題
- **100**: 確実。再確認して本物であり、頻繁に起きることを証拠が直接示している

## 結果の扱い

| verdict | ローカル表示 | PR 投稿 |
|---|---|---|
| CONFIRMED（confidence 80 以上） | 指摘として表示 | 対象 |
| CONFIRMED（80 未満） | 指摘として表示 | 対象外 |
| PLAUSIBLE | 「要確認」として表示 | 対象外 |
| REFUTED | 除外。要旨と理由を 1 行ずつ表示 | 対象外 |

REFUTED が全体の半分を超えた場合は、レビュアーが過検知気味であることを結果表示の冒頭で 1 行伝える。
