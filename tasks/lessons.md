## L-1. 「古い」「未使用」の判定は事実確認を経てから

**発生**: 2026-04-19, F-1（Emacs古いパッケージ削除）作業中
**誤り**: `helm`, `auto-complete`, `smartparens`, `org2blog`, `enh-ruby-mode` を「古い」と判断して削除しようとした
**実態**: すべて 2025-2026 に更新のある現役パッケージ（GitHub API で確認）
**教訓**:
- 「古い」と言うなら **最終更新日 / archived フラグ** で裏取りする
- 「使っていない」と言うなら **ユーザーに実使用を確認** する
- 計画ドキュメントにある項目でも、削除前に事実確認を一段挟む
- 特に破壊的な削除（ファイル・パッケージ）は F-1 のような巻き戻しコストが高い

**適用場面**: Brewfile / パッケージリスト / 設定ファイルの削除系タスク全般

## L-2. `git rm` 済みファイルを `git add` しない

**発生**: B-1, D-4 での commit-draft 失敗
**誤り**: `git rm` で staging 済みの削除ファイルを、commit-draft スクリプトの `git add` に含めてしまい `pathspec did not match any files` エラー
**教訓**:
- commit-draft 生成前に `git status` で staged / unstaged を確認する
- すでに staged な削除は `git add` から外す。新規の modified のみ `git add` する

**適用場面**: `git rm` で削除したファイルを含むコミットを作るとき

## L-3. fish exec をしない理由は「fish 非対応・動作が不安定」

**発生**: 2026-04-19, C-2（`should_exec_fish` 関数化）で誤ったコメントを書いた
**誤り**: zshrc_mac で IDE / Warp で `exec fish` しない理由を「それぞれ独自の補完・履歴機能があるため」と記述した
**実態**: 真の理由は「fish に対応していない or fish 起動で動作が不安定になるツールがあるため個別判定で zsh に残している」
**教訓**:
- 既存コードの意図を勝手に解釈しない。条件の理由が書かれていないときは確認するか、事実ベース（「このツールでは fish を起動しない」）だけ書く
- IDE 独自機能の有無は、zsh に残す理由ではない。重要なのは **fish が動くかどうか**

**適用場面**: `zshrc_mac` / `zshrc_linux` の `should_exec_fish` 判定を拡張するとき。新しいツールを追加する際は「fish がそこで動くか・安定するか」で判断する


## L-4. 共有スキルの保存先は実行元ごとに解決する

**発生**: 2026-09-15、Codex の会話が Claude Code 用ディレクトリに保存された。
**教訓**: ログ形式だけでなく既定保存先にも実行元を渡す。明示 PATH は優先し、既定値・別名・自動判定の保存結果を検証する。

## L-5. 修正の検証は「初回・2 回目」だけでなく定常状態と境界入力まで追う

**発生**: 2026-10-26, PR #27 のレビューで 9 件の指摘を受けた
**誤り**:
- compinit の 24h 判定: dump 無し / 24h 以内 / 25h 経過 の 3 パターンは確認したが、「25h 経過で通常 compinit が走った *その次* の起動」を見ておらず、mtime が進まないため翌日以降ずっと遅い分岐に入ることを見逃した
- pre-commit hook: ファイル名をそのまま git の pathspec に渡し、`:` 始まり・glob 文字を含む名前で検査漏れ・巻き込みが起きた。`--diff-filter=ACMR` で型変更 T を落とした。`git diff-index --check` の併記形式を末尾一致 grep で落とした
- `read -r X || X=""`: 改行なし EOF では読めた値が入ったまま 1 が返るため、読めた回答を捨てていた
**教訓**:
- 時間や mtime に依存する判定は、条件を跨いだ **直後の 1 回** まで確認して定常状態に戻ることを見る
- ユーザー由来の文字列を git の pathspec に渡すときは `:(literal)` を前置する。`--diff-filter` は除外したいものを小文字で指定する（`d`）方が漏れない
- ただし git hook は呼び出し元の `GIT_*_PATHSPECS` 環境変数を引き継ぐ（Magit は `--literal-pathspecs` が既定）。`:(literal)` に頼る hook は冒頭で `unset GIT_LITERAL_PATHSPECS GIT_GLOB_PATHSPECS GIT_NOGLOB_PATHSPECS GIT_ICASE_PATHSPECS` してから使う
- 規則を lessons に書いたら、同じファイル内の他の箇所（今回は行末空白除去後の `git add`）にも同じ規則を適用したか見直す
- ツール出力を grep で拾うときは、併記・派生形式に備えて `(\.|, [^:]*\.)$` のように**行末を固定したまま**広げる。行末固定を外すと同じ出力に混ざる本文行（`git diff-index --check` は問題行の本文も出す）にマッチする。取り出した値は file が検査対象に含まれるか・line が数値かまで検証する
- `read` の前に変数を初期化する。fd 自体が閉じている（`<&-`）と `read` は代入せずに失敗し、`set -u` で落ちる
- `cmd || fallback` で変数を上書きするときは、失敗時にも変数が部分的に埋まる可能性を考える

**適用場面**: シェルスクリプトの修正全般。特にキャッシュ判定・git hook・対話入力の扱い
